\subsection{Teacher Model}
\label{sec:teacher}

\begin{itemize}
    \item Teacher is \textbf{PET2}, the OmniLearned backbone: local $k$NN
    interaction blocks ($K{=}15$) + global multi-head self-attention over
    per-particle tokens.
    \item \emph{Large} config: 28 transformer blocks, 4 local-interaction
    heads, \texttt{base\_dim}$=1024$, 32 attention heads.
    \item Fine-tuned directly on top tagging, checkpoint tag
    \texttt{fine\_tune\_top\_l}.
    \item Frozen for every KD run in this report, including the DeepSets
    student.
\end{itemize}

\subsection{Distillation Pipeline}
\label{sec:pipeline}

\begin{itemize}
    \item Teacher logits computed once, offline, on train/val splits
    (\texttt{omnilearned evaluate}), cached as per-event \texttt{.npz}.
    \item Converted to companion H5 files aligned to train/val events
    (\texttt{build\_teacher\_h5.py}); training reads cached logits, never
    re-runs the teacher.
    \item Student trained with
    $\mathcal{L}=\alpha\mathcal{L}_{\mathrm{CE}}+\beta T^2 D_{\mathrm{KL}}(\hat y/T\,\|\,\hat y_{\mathrm{teacher}}/T)$,
    default $\alpha{=}0.5,\beta{=}0.5,T{=}4$.
    \item Evaluated on the held-out 404{,}000-event test split
    (\texttt{omnilearned evaluate --arch deep-sets}): Accuracy, AUC,
    $1/\mathrm{FPR}_{50\%}$, $1/\mathrm{FPR}_{30\%}$.
\end{itemize}

\subsection{DeepSets Student Architecture}
\label{sec:deepsets-arch}

\begin{itemize}
    \item Permutation-invariant Deep Sets classifier,
    $f(X)=\rho(\operatorname{pool}_{x\in X}\phi(x))$: per-particle embedding
    $\phi$ (\texttt{DeepSetsBody}) + global classifier $\rho$
    (\texttt{DeepSetsHead}), masked mean-pooling as the only
    order-discarding op.
    \item Input: 4 raw kinematic features/particle, zero-padded, mask
    $m_n=\mathbb{1}[x_{n,2}\neq0]$; norm is \texttt{DynamicTanh}
    ($\tanh(\alpha x)\odot\gamma$), activation GELU.
    \item Three original size presets (small/medium/large), later extended
    below ``small'' (Section~\ref{sec:deepsets-size-scan}).
    \item GELU is non-standard for hls4ml; a hardware variant would swap in
    ReLU (see Section~\ref{sec:deepsets-hls4ml}). \texttt{DynamicTanh},
    despite being a custom module, exports to supported ONNX ops
    ($\mathrm{Mul}\circ\tanh\circ\mathrm{Mul}$) and does \emph{not} need
    replacing.
\end{itemize}

\subsection{DeepSets with a Message-Passing Block}
\label{sec:deepsets-gnn}

\begin{itemize}
    \item Optional \texttt{DeepSetsInteraction} block: one EdgeConv /
    Interaction-Network layer inserted between the embedding and the $\phi$
    blocks. For every ordered pair $(i,j)$ a shared edge MLP maps
    $[h_i, h_j, e_{ij}]$ to a message, with
    $e_{ij}=(\log m_{ij},\,\log\Delta R_{ij},\,\log k_{T,ij})$ -- the same
    three physics quantities PET2's interaction block uses. Messages are
    mean-pooled over valid neighbours and added back as a pre-norm residual;
    the body stays permutation-equivariant, the masked pool keeps the whole
    model invariant.
    \item Opt-in and checkpoint-compatible: \texttt{--num-interaction-layers}
    $N$ (default 0 $=$ plain Deep Sets, no modules built) and
    \texttt{--interaction-k} $K$ (leading-$p_T$ constituent cap, a plain
    slice since inputs are stored $p_T$-descending) bound the $O(N^2)$
    message-passing cost.
    \item Trained config \texttt{distillnet+GNN}: \texttt{distillnet} body
    ($d{=}32$, $L_\phi{=}2$, $L_\rho{=}1$) $+$ one interaction block, $K{=}64$,
    $\sim$17{,}446 params (body 13{,}155 $+$ head 4{,}291; the block adds
    $\sim$6{,}465 over plain \texttt{distillnet}). Same $\alpha{=}0.5$,
    $\beta{=}0.5$, $T{=}4$ KD recipe, large teacher, 50 epochs.
\end{itemize}

        \textbf{DeepSets-KD, distillnet+GNN} & \textbf{17{,}446} & \textbf{93.98\%} & \textbf{0.9859} & \textbf{449.7} & \textbf{1979.5} \\
        DeepSets-KD, distillnet (plain)    & 10{,}981 & 92.85\% & 0.9800 & 199.1 & 747.8 \\
        \bottomrule

    \caption{One message-passing block vs.\ plain Deep Sets, same

    \label{tab:deepsets-gnn-result}

\begin{itemize}
    \item Best DeepSets student to date. Versus plain \texttt{distillnet}
    (same width class, $+6{,}465$ params): $+1.13$ accuracy points,
    AUC $+0.0059$, background rejection $\sim$2.3--2.6$\times$
    ($199\to450$ at $50\%$, $748\to1980$ at $30\%$).
    \item Beats the $27\times$-larger plain ``small'' student
    (298{,}887 params) on every metric, and closes most of the rejection
    gap to the PET2 teachers ($\sim$1/3 of teacher rejection $\to$
    $\sim$0.7--0.8$\times$). Pairwise kinematics are exactly what pure
    sum-pooling Deep Sets discards.
    \item Cost: the $O(K^2)$ all-pairs edge MLP dominates FLOPs.
    Analytic count (\texttt{FlopCounterMode}): plain \texttt{distillnet}
    $\sim$1.93 MFLOP/jet at the 150-slot padded input;
    \texttt{distillnet+GNN} saturates at $\sim$52.7 MFLOP/jet
    (constant for $N\ge64$ thanks to the leading-$p_T$-64 slice)
    $\Rightarrow$ $\sim$27$\times$ plain \texttt{distillnet},
    $\sim$3.3$\times$ the 299k-param plain ``small'' (15.8M).
    \item Single run, no seed spread yet -- the $+0.68$ acc-point margin
    over the ``small'' student is well outside the $\sim$0.002 replication
    std of the other family members, so likely real, but a rep is
    outstanding.
\end{itemize}

    $-0.03$ accuracy points, AUC $-0.0003$, rejection $-3.6\%$ at $50\%$ /

    edge MLP) wrapped; the physics edge-feature extraction has no linear
    layers and is left in float. The message-passing block quantizes
    cleanly -- no sign of quantization hostility.
    \item Neither model is fundamentally quantization-hostile: the weights
    just need adapting to the quantization grid via fine-tuning.
    \item Still a pure PyTorch accuracy simulation -- no FPGA synthesis.
    See Section~\ref{sec:deepsets-hls4ml} for the QONNX export and
    \texttt{hls4ml} ingestion attempt.
\end{itemize}

\subsection{QONNX Export and \texttt{hls4ml} Ingestion}
\label{sec:deepsets-hls4ml}

\paragraph{FPGA-readiness status.}
\begin{itemize}
    \item \textbf{PTQ:} not viable at any useful bit width
    (Section~\ref{sec:deepsets-ptq}).
    \item \textbf{8-bit QAT:} validated for both the plain \texttt{distillnet}
    and the \texttt{distillnet+GNN} student -- near-lossless accuracy
    (Section~\ref{sec:deepsets-qat}).
    \item \textbf{QONNX export:} done and numerically validated for the
    8-bit QAT checkpoints.
    \item \textbf{\texttt{hls4ml} ingestion:} blocked -- the current
    Deep Sets graph is not expressible in \texttt{hls4ml}'s supported
    operator set (architecture-level gap, not a precision gap).
    \item \textbf{HLS synthesis:} not attempted -- no Vivado / Vitis HLS on
    the system, so real LUT / DSP / BRAM / latency numbers are not
    obtainable here regardless.
\end{itemize}

\paragraph{QONNX export (Brevitas).}
\begin{itemize}
    \item Brevitas 0.13 \texttt{export\_qonnx} (torch-2.9 dynamo exporter
    path); requires \texttt{onnx} $+$ \texttt{onnxoptimizer} (the latter
    added to the FPGA environment for this step).
    \item A thin wrapper is exported, not \texttt{DeepSets} directly:
    forward $= \rho(\mathrm{body}(x))$, i.e.\ raw
    $(B, 2)$ logits -- dropping the model's dict output and its unused
    label argument, which ONNX tracing does not accept.
    \item Post-export: QONNX \texttt{InferShapes} $+$ \texttt{FoldConstants}
    $+$ readable names. The cleaned graph has a single input
    $[B, 150, 4]$, a single output $[B, 2]$, passes \texttt{onnx.checker},
    and imports opsets \texttt{ai.onnx} 20 $+$ \texttt{qonnx.custom\_op.general}
    2 (genuine QONNX).
    \item \texttt{distillnet+GNN} graph: 135 nodes, 18 \texttt{Quant} ops
    (9 \texttt{QuantLinear} $\times$ weight $+$ activation).
    \item \textbf{Parity vs.\ PyTorch} (via the QONNX executor -- stock
    \texttt{onnxruntime} cannot run the \texttt{Quant} custom op):
    $\max|\Delta\,\mathrm{logit}| = 3.9\times10^{-3}$ at batch 64,
    $9.5\times10^{-7}$ at batch 1; 100\% argmax agreement; identical batch
    accuracy. The export is faithful.
    \item Static batch dimension is baked in at export time (re-run per
    target batch size); a batch-1 variant is also exported. The plain
    \texttt{distillnet} QAT checkpoint (7 \texttt{QuantLinear}) was exported
    the same way.
\end{itemize}

\paragraph{\texttt{hls4ml} ingestion (v1.3.0, QONNX front-end).}
\begin{itemize}
    \item Flow: QONNX \texttt{cleanup\_model} $+$ \texttt{GemmToMatMul},
    then \texttt{config\_from\_onnx\_model} (backend Vitis,
    \texttt{io\_stream}).
    \item \texttt{hls4ml} 1.3 supported ONNX ops: \texttt{Conv},
    \texttt{MatMul} / \texttt{Gemm}, \texttt{Transpose},
    \texttt{Reshape} / \texttt{Flatten} / \texttt{Resize} / \texttt{Pad},
    \texttt{Relu} / \texttt{Tanh} / \texttt{Sigmoid} / \texttt{LeakyRelu} /
    \texttt{Elu} / \texttt{Selu} / \texttt{PRelu} / \texttt{Softmax} /
    \texttt{Softsign} / \texttt{Softplus}, \texttt{BatchNormalization},
    \texttt{Quant} / \texttt{IntQuant} / \texttt{BipolarQuant},
    \texttt{Add} / \texttt{Sub} / \texttt{Mul} / \texttt{Div} /
    \texttt{Average} / \texttt{Max} / \texttt{Min} / \texttt{Concat} /
    \texttt{Sum}, \texttt{\{Global\}\{Max,Average\}Pool}.
    \item \textbf{Plain \texttt{distillnet}} cleaned graph: 53 nodes,
    7 unsupported op types -- \texttt{Gelu} ($\times3$),
    \texttt{ReduceSum} ($\times2$), \texttt{Slice}, \texttt{Cast},
    \texttt{Clip}, \texttt{Equal}, \texttt{Not}. Sources: the GELU
    activation; the masked-mean pool (\texttt{ReduceSum} / \texttt{Slice});
    the in-graph mask $\mathbb{1}[x_{n,2}\neq0]$
    (\texttt{Equal} / \texttt{Not} / \texttt{Cast}); a residual
    quantizer clamp (\texttt{Clip}).
    \item \textbf{\texttt{distillnet+GNN}} cleaned graph: 132 nodes,
    19 unsupported op types -- the above plus \texttt{Exp} ($\times4$),
    \texttt{Expand} ($\times4$), \texttt{Gather} ($\times6$),
    \texttt{Unsqueeze} ($\times10$), \texttt{Greater} ($\times3$),
    \texttt{Log} ($\times3$), \texttt{Where} ($\times3$),
    \texttt{Pow} ($\times2$), \texttt{Cos}, \texttt{Cosh},
    \texttt{ReduceMin}, \texttt{Sqrt}. Sources: the transcendental edge
    features ($\log m$, $\log\Delta R$, $\log k_T$); the all-pairs
    broadcast (\texttt{Expand} / \texttt{Gather} / \texttt{Unsqueeze}).
    \item Both fail in \texttt{config\_from\_onnx\_model} $\to$
    \texttt{parse\_onnx\_model} with
    \texttt{ERROR: Unsupported operation type: Slice} (the first unsupported
    node; many more behind it).
    \item \texttt{DynamicTanh} survives: it exports as
    $\mathrm{Mul}(\tanh(\mathrm{Mul}(\alpha, x)),\,\gamma)$, all supported
    ops -- contrary to the earlier expectation that the norm would also
    need swapping. The blockers are GELU, in-graph masking/pooling, and
    (GNN only) the edge-feature math and all-pairs broadcast.
\end{itemize}

\paragraph{Path forward.}
\begin{itemize}
    \item \textbf{\texttt{hls4ml}-friendly variant:} swap GELU $\to$ ReLU
    (\texttt{act\_layer} is a constructor argument, already verified to
    instantiate and forward cleanly), and move the masking and pooling out
    of the synthesised graph (fixed-$N$ input $+$ \texttt{GlobalAveragePool},
    or a host-supplied mask). Then retrain (float KD) $+$ re-QAT. Targets
    the plain \texttt{distillnet}, which then maps $\sim$1:1 onto the
    classic \texttt{hls4ml} jet tagger.
    \item \textbf{GNN on FPGA is research-grade:} the edge features would
    have to be host-precomputed and fed as an extra input (splitting the
    model), and the all-pairs \texttt{Expand} / \texttt{Gather} tensor is a
    dataflow/routing cost \texttt{hls4ml} handles poorly even then. The
    $\sim$27$\times$ FLOP ratio over plain \texttt{distillnet} is a lower
    bound on the hardware gap.
    \item \textbf{HGQ} (High Granularity Quantization, arXiv:2405.00645):
    per-parameter learnable bit-widths, gradient-optimised against a
    bit-operations resource penalty; the state-of-the-art \texttt{hls4ml}
    precision method (and the recommended next step in arXiv:2512.17011).
    Keras-based, not in the current environment, and orthogonal to the
    operator-support blocker -- relevant only once an
    \texttt{hls4ml}-expressible architecture and a synthesis machine
    exist.
\end{itemize}
