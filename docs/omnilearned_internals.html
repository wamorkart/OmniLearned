1. Overview

OmniLearned is a foundation-model framework for jet physics. The core network — called PET2 (Point-Edge Transformer v2) — treats every event as a variable-length point cloud of particles. The same backbone serves classification, regression, segmentation, flavour-tagging, and generative diffusion tasks, and can be pre-trained jointly across many datasets and then fine-tuned on a downstream task.

Three things to keep in mind:

  • Inputs are (N, M, F) tensors: N events, up to M particles per event (zero-padded), F per-particle features.
  • The network has a shared body that produces particle embeddings, plus task-specific heads (classifier and/or generator).
  • The mode (--mode classifier|generator|pretrain|regression|segmentation|ftag) selects which heads are built, which losses fire, and how the data is interpreted.
┌────────────────────── PET2 ──────────────────────┐ input → │ PET_body → shared particle embeddings │ → classifier head → y_pred (logits) │ ↑ │ → generator head → z_pred (velocity / per-particle class) │ conditioning: cond / pid / add_info / time │ └───────────────────────────────────────────────────┘

3. Inputs: data format and per-feature semantics

Every dataset is a directory of HDF5 files split into train/, test/, val/ subfolders. The dataloader walks all *.h5 files in a split, builds a flat index of (file_idx, sample_idx) pairs, shards it across DDP ranks, and yields collated mini-batches.

3.1 Required HDF5 datasets

KeyShapeMeaning
data(N, M, F)Per-particle features (kinematic + optional PID + optional add-features)
pid(N,) or (N, K)Event-level label (class index for classification; vector for regression)
global(N, G)Optional jet-level / event-level conditioning features (mass, pT, multiplicity, ...)
data_pid(N, M) or (N, M, K)Per-particle labels (used by segmentation and ftag modes)

3.2 Kinematic features (the first 4 channels of data)

The canonical “jet” ordering is:

  1. Δη — pseudorapidity difference between particle and jet axis
  2. Δφ — azimuthal angle difference between particle and jet axis
  3. log pT — log of particle transverse momentum
  4. log E — log of particle energy
Padding convention: a particle is treated as “real” iff its third feature (index 2, i.e. log pT) is non-zero. This is computed everywhere as mask = x[:, :, 2:3] != 0 (see network.py:543, diffusion.py:60, etc.). Zero-pad rows to the maximum particle count in the dataset.

3.3 Optional extra channels: PID and additional features

Beyond the 4 kinematic features, data can carry:

  • PID — one integer column at --pid-idx (default 4). Enabled with --use-pid. The dataloader splits it out into sample["pid"] and removes that column from X.
  • Additional features — the last --num-add columns. Enabled with --use-add. The dataloader pops them into sample["add_info"] and removes them from X.

So with --use-pid --use-add --num-add 4 on a 9-feature file, X goes from 9 → 4 kinematic features, while pid and add_info are passed separately into the model. This is why --num-feat must equal the post-split kinematic count, not the raw column count.

Common pitfall: if you don’t pass --use-pid / --use-add at evaluate time but the checkpoint was trained with them, the dataloader feeds 9 columns into a network whose InputBlock was sized for 4 — you’ll see RuntimeError: size of tensor a (9) must match tensor b (4) at non-singleton dimension 2.

4. Modes

The --mode flag selects what the model does. Internally, in PET2.__init__ it decides which heads to instantiate and which losses to compute:

Mode Classifier head Generator head What gets returned Typical use
classifier✓—y_pred (logits)Jet tagging, ID
regression✓—y_pred (continuous)Regress jet quantities
pretrain✓✓ (diffusion)y_pred, y_perturb, z_predJoint generative + classification pretraining
generator—✓ (diffusion)z_pred (velocity)Particle-cloud generation
segmentation—✓ (per-particle classification)z_pred (per-particle logits)Per-particle labelling
ftag✓✓ (per-particle track origin classification)y_pred + z_predFlavour tagging (jet + track-origin)

Key wiring in PET2.forward (network.py:144):

if self.mode in ["generator", "pretrain"]:
    z, v, v_weight = perturb(x, time)              # noise the input
    z_body = self.body(z, cond, pid, add_info, time)
    z_pred = self.generator(z_body, y)

if self.mode in ["classifier", "regression", "segmentation",
                 "pretrain", "ftag"]:
    x_body = self.body(x, cond, pid, add_info, torch.zeros_like(time))
    if mode in ["classifier", "pretrain", "regression", "ftag"]:
        y_pred = self.classifier(x_body)
    if self.mode == "pretrain":
        y_perturb = self.classifier(z_body)        # contrastive-style aux head
    if self.mode in ["ftag", "segmentation"]:
        z_pred = self.generator(x_body, y)         # per-particle head on clean inputs

So in pretrain mode the same body is run twice (clean and noised) and the classifier is applied to both — the noised pass is what enables the joint diffusion+classification objective.

5. Architecture: PET2 in detail

PET2 (network.py:18) is a thin wrapper that owns three things:

  • self.body — the shared PET_body that turns a point cloud into a sequence of contextual embeddings.
  • self.classifier — the PET_classifier head (only built for classifier-style modes).
  • self.generator — the PET_generator head (only built for generative / per-particle modes).

5.1 PET_body — the shared backbone

raw x (B,M,F) │ │ mask = x[:,:,2:3] != 0 │ ├──▶ InputBlock(x, mask) ──── x_embed (global per-particle MLP) │ ├──▶ LocalEmbeddingBlock ──── local_features (kNN graph + transformer) │ (kNN over first num_coord features; each particle attends to its K │ nearest neighbours via an attention stack) │ ├──▶ InteractionBlock (optional) ──── x_int (B*H, M, M) bias added to attention │ (pairwise physics features: log-mass, log-ΔR, log-kT, ... per pair) │ │ x = x_embed + local_features │ x = x + pid_embed(pid) · if --use-pid │ x = x + add_embed(add) · if --use-add │ x = [cond_token, x] · if --conditional │ x = [time_token, x] · if mode in {generator, pretrain} │ x = [class_tokens, x] · num_tokens learnable summary tokens prepended │ ├──▶ Stack of AttBlock × num_transformers (with optional U-Net skips) │ └──▶ DynamicTanh norm × mask → contextual embeddings

Important construction details:

  • Class tokens: num_tokens learnable summary tokens are prepended to every event. Default 4. The classifier head reads only these.
  • num_add in the body tracks how many extra non-particle tokens were prepended (cond token, time token). Heads need this to know where the “real” particles start.
  • Skip connections: with skip=True, the transformer stack is split into halves with U-Net-style skips wired through AttBlock.skip_linear.
  • Interaction bias: when use_int=True, pairwise physics features are turned into a per-head (B·H, M, M) tensor that’s added to the attention mask of every block. This is added only to the particle-particle sub-block (not to the prepended tokens).

5.2 PET_classifier — the classification head

(network.py:191)

  • Stack of TokenAttBlock layers: cross-attention from the num_tokens learnable summary tokens into the particle sequence (the tokens are queries, the particles are keys/values).
  • Concatenates the num_tokens token outputs, runs an MLP, and projects to num_classes via nn.Linear.

5.3 PET_generator — the generative / per-particle head

(network.py:255)

  • For diffusion: prepends an nn.Embedding(num_classes, base_dim) for the class label y, runs another transformer stack with full self-attention, then projects every particle slot back to input_dim (the predicted velocity).
  • For segmentation / ftag: num_gen_classes > 1 swaps the output projection to num_gen_classes logits per particle, and skip_pid=True drops the class embedding (we’re classifying tracks, not generating them).

6. Building blocks (layers.py)

BlockWhat it does
DynamicTanh Cheap replacement for LayerNorm: x → weight · tanh(α·x). α and per-channel weight are learnable. Used as the default norm_layer everywhere.
LayerScale Per-channel learnable scale (γ) applied after residual blocks; supports masked inputs.
NoScaleDropout Bernoulli token-drop without the usual 1/(1-p) rescaling — used to drop PID / extra-feature tokens stochastically during training.
MLP Two-layer MLP Linear → act → norm → drop → Linear → drop, optionally masked.
InputBlock Per-particle embedding: norm(x) → MLP from input_dim → base_dim. This is where the size-mismatch errors surface if --num-feat doesn’t match the data.
LocalEmbeddingBlock kNN graph + local transformer. For each particle: find K nearest neighbours in coordinate space, compute relative features (and optionally local interaction features), run num_transformers_head attention blocks, average-pool over neighbours back to one vector per particle.
InteractionBlock Computes a pairwise feature tensor (B,M,M,3) using one of three physics-aware feature sets, MLP-projects it to num_heads channels, and reshapes to a (B·H, M, M) additive attention bias.
AttBlock Standard pre-norm transformer block: MHA + MLP residuals, supports an additive attention mask and an optional U-Net skip via skip_linear.
TokenAttBlock Variant used in the classifier head: only the first num_tokens rows act as queries; they attend to the rest of the sequence. Cheaper than full self-attention.
MPFourier (diffusion.py) Random-frequency Fourier features for the diffusion time t ∈ [0,1]. Output is fed through time_embed and prepended as a token.

6.1 The three interaction modes

Set by --interaction-type:

  • lhc (default) — [log m², log ΔR, log kT]. Standard collider-physics pair features.
  • astro — [log Δ3d, log(1-cosθ), log(1-cosθ_diff)]. 3D Euclidean / cosine features.
  • ot — Sinkhorn / sliced Wasserstein distance computed in a sliding window via get_swd.

Choose with the dataset domain in mind; the lhc set assumes (Δη, Δφ, log pT, log E) kinematics.

8. Training pipeline

Entry point: train.run() (train.py:392). High-level flow:

1. ddp_setup() → init torch.distributed (NCCL) 2. PET2(**model_params) → build model in the requested mode/size 3. load_data(train) / load_data(val) → HEPDataset + DataLoader (sharded by rank) 4. get_param_groups(...) → separate decay vs no-decay, scale LR on new layers 5. Lion / AdamW + cosine / onecycle → optimizer + LR schedule 6. DDP(model) + shadow_copy → ema_model → wrap, build EMA shadow 7. (optional) restore_checkpoint → resume or fine-tune 8. for epoch: train_step + val_step → standard loop, checkpoint on best val

8.1 Optimizer & schedule

  • Lion (default) or AdamW, with separate parameter groups:
    • decay vs no-decay — {"norm","token"} parameters never get weight decay.
    • new-layer vs pretrained-layer — on fine-tune, “new” layers (classifier.out, generator, body.cond, body.add_embed, body.local_physics, body.embed, body.interaction) use a higher LR via --lr-factor.
  • Cosine schedule with warmup (default) or OneCycleLR.
  • Gradient clipping at norm 1.0 every step.
  • AMP is opt-in with --use-amp; uses torch.amp.GradScaler.

8.2 EMA

An exponential-moving-average shadow copy is always created (shadow_copy). After every backward pass:

ema_p.mul_(ema_decay).add_(model_p, alpha=1.0 - ema_decay)   # default decay = 0.9999

Generative inference (evaluate.run with --mode generator) restores the EMA weights, not the live ones — this is the standard diffusion practice.

8.3 Checkpointing

save_checkpoint writes a dict with separate sub-state-dicts:

{
  "body":            model.module.body.state_dict(),
  "classifier_head": ... if classifier is not None,
  "generator_head":  ... if generator  is not None,
  "ema_body":        ... ,
  "ema_generator":   ... ,
  "optimizer":       optimizer.state_dict(),
  "sched":           lr_scheduler.state_dict(),
  "epoch":           ...,
  "loss":            ...,
}

Because heads are stored separately, fine-tuning can load just the body and reinitialise the classifier output layer for a new label space. restore_checkpoint(..., fine_tune=True) implements that by filtering on shape match and explicitly skipping any key containing "out.".

8.4 Knowledge distillation (offline)

If --distill is passed, the dataloader loads pre-saved teacher logits from a directory of outputs_*.npz files (produced earlier by omnilearned evaluate) and adds a KL term:

loss = α · task_loss + β · T² · KL(softmax(student/T) ‖ softmax(teacher/T))

Defaults: α=β=0.5, T=4.

9. Losses

All losses live in utils.get_loss (utils.py:207). The function looks at the outputs dict and adds whichever terms are non-None.

9.1 Classification loss

  • Weighted cross-entropy: per-batch class weights 1/(count_c + 1e-6), normalised to mean 1. This counteracts class imbalance without needing an explicit sampler.
  • --use-event-loss: splits the 210 logits into two heads — [0..199] for jet types, [200..209] for event types — and applies CE to whichever block the label falls into. See get_class_loss in utils.py:181.

9.2 Generator / diffusion loss

For diffusion (modes generator, pretrain):

loss_gen = v_weight · MSE(v, z_pred).sum(particles) / num_nonzero_particles

where v = ε - x (velocity parameterisation, see §10).

For per-particle classification (modes segmentation, ftag), the generator head outputs per-particle logits and the loss is masked CE against data_pid.

9.3 Auxiliary heads

  • y_perturb (only in pretrain mode): same classifier applied to the noised embeddings. Adds a second weighted-CE term, weighted by α² = (1-t)² so clean examples count more.
  • --use-clip: AstroCLIP-style contrastive loss between clean and noised body embeddings (CLIPLoss in utils.py:85). Encourages the body to keep noised representations close to clean ones for the same example.
  • Distillation: see §8.4.

10. Diffusion: noise schedule, sampling

The diffusion implementation in diffusion.py is intentionally minimal:

10.1 Schedule

Linear “rectified flow”-style schedule with α(t) = 1 - t, σ(t) = t for t ∈ [0,1]:

z(t) = α(t) · x  +  σ(t) · ε
v(t) = ε - x        # velocity target the network learns to predict
logSNR(t) = -2 log(σ/α)

10.2 Noise distribution

get_ad_eps samples ε from a Gaussian with empirically-calibrated means and stds for the 4 kinematic channels of the published datasets:

means = [0.0, 0.0, 1.11398, 1.43384]
stds  = [0.270949, 0.27426, 1.30273, 1.33559]

If your input has >4 channels, the extras get unit-Gaussian noise. The mask is applied so zero-padded slots stay zero.

10.3 Sampling

generate integrates the learned velocity field with a midpoint ODE solver (torchdiffeq.odeint) over nsteps=128 steps from t=1 → t=0. Particle multiplicity per event is read from the conditioning vector (cond[:, multiplicity_idx]) and used to build the per-event mask before integration.

11. Evaluation

evaluate.run() (evaluate.py:165) builds the model exactly as train.run would, then:

  1. Loads the checkpoint (EMA weights iff --mode generator).
  2. Wraps in DDP and runs eval_model → test_step over the chosen split.
  3. Saves a per-rank npz (classification / regression / segmentation) or h5 (generator).

11.1 Output file naming

Per-rank files in --output_dir:

outputs_{save_tag}_{dataset}_{dataset_type}_{rank}.npz   # classifier / regression / segmentation
generated_{save_tag}_{dataset}_{dataset_type}_{rank}.h5  # generator

12. Worked examples

12.1 From scratch on top-tagging (small)

omnilearned train -o ./ --save-tag top_s \
    --dataset top --path /your/datasets \
    --size small --epoch 15 --lr 5e-4 \
    --wd 0.5 --interaction

4 kinematic features (default --num-feat 4), no PID, no extras, lhc interaction bias on, cosine LR with no warmup, Lion optimiser.

12.2 The published pretrain_l recipe

omnilearned train -o /checkpoints/ --save-tag pretrain_l \
    --mode pretrain --dataset pretrain --num-classes 210 \
    --epoch 500 --iterations 1000 --batch 8 --num-workers 32 \
    --lr 1e-5 --wd 0.1 --optim lion --size large \
    --feature-drop 0.1 \
    --use-pid --use-add --use-event-loss --interaction \
    --wandb --resuming

What that means in plain terms:

  • Mode pretrain: joint diffusion + classification on the mixed pretrain dataset.
  • 210 classes: 200 jet types + 10 event types (see §3.5).
  • --use-pid --use-add: the data has PID at index 4 and 4 extra features at the end; the dataloader splits them out, leaving 4 kinematic features for the body.
  • --use-event-loss: split the 210 logits into the 200-jet and 10-event heads (see §9.1).
  • --feature-drop 0.1: stochastically drop the PID / add-feature tokens 10% of the time during training, so the model isn’t overly reliant on them.

12.3 Fine-tune the pretrain checkpoint on top-tagging

omnilearned train -o /checkpoints/ --save-tag fine_tune_top_l \
    --dataset top --batch 8 --epoch 5 \
    --wd 10.0 --lr 1e-6 --size large --num-workers 4 \
    --fine-tune --pretrain-tag pretrain_l --interaction

Loads pretrain_l’s body and classifier (minus the output linear), wires up a fresh num_classes-way output for the new label space, and trains with a tiny LR.

12.4 Evaluating the pretrain checkpoint on ATLAS

omnilearned evaluate -i /checkpoints/ -o /out/ \
    --save-tag pretrain_l --dataset atlas --size large \
    --path /global/cfs/cdirs/m4567/www/ \
    --num-classes 210 --batch 64 --num-workers 4 \
    --interaction --use-pid --use-add --use-event-loss \
    --dataset-type val
The --use-pid --use-add --use-event-loss trio must match the training recipe, otherwise the dataloader feeds the wrong number of channels into the body and you’ll get the dimension-mismatch RuntimeError at DynamicTanh.forward.
